# 任务分工表 — 架构师 × Codex

> 生效日期：2026-10-31 ｜ 协议版本 1.0 ｜ 维护方：架构师（锻码师）

## 一、总览

| 角色 | 身份 | 一句话职责 |
|---|---|---|
| **锻码师**（WorkBuddy） | 架构师 / 技术负责人 | 定方向、拆任务、验结果、管仓库 |
| **Codex** | 实现工程师 | 按契约写代码、自检、交付报告 |
| **王上** | 产品负责人 | 定目标、拍板范围、最终验收 |

## 二、逐环节分工

| # | 环节 | 锻码师 | Codex | 王上 | 交接物 |
|---|---|---|---|---|---|
| 1 | 需求澄清 | 提问收敛（规模/团队/阶段/约束），写约束清单 | — | 回答、拍板 | 工程档案 §1 |
| 2 | 技术选型 | 决策矩阵 + 推荐 + 切换条件 | — | 确认 | 工程档案 §2、ADR |
| 3 | 架构设计 | 分层、模块边界、数据流、ADR 登记 | — | 知情 | `docs/ARCHITECTURE*.md` |
| 4 | 任务拆解 | 拆到「单文件可验收」粒度，写契约 | — | — | `.codex/tasks/ACTIVE.md` |
| 5 | 任务下发 | 改 `STATE.json` 为 `READY`，推送 | 读 `AGENTS.md` → 认领 | 打开 Codex 执行一句 | `STATE.json` |
| 6 | **代码实现** | ❌ 不写业务代码 | ✅ 全部实现 | ❌ 不插手 | `src/**` |
| 7 | 自检 | 定义自检命令与门槛 | 跑 `npm run build`、grep 校验 | — | 报告「自检命令输出」节 |
| 8 | 交付 | — | 写 `reports/TASK-00X-REPORT.md`，改 `STATE` 为 `SUBMITTED` | — | 报告文件 |
| 9 | **评审** | ✅ 逐条对验收清单，出 🔴/🟠/🟡 | ❌ 不自评、不自过 | 看结论 | `review/TASK-00X-REVIEW.md` |
| 10 | 返工 | 判定 `CHANGES_REQUESTED`，列修复要求 | 只修 🔴+🟠，逐条响应，`round`+1 | — | 报告「第 N 轮修复」 |
| 11 | 通过 | 判定 `APPROVED`，推进 `stage`、下发下一任务 | 待命 | 知情 | `STATE.json` |
| 12 | **提交推送** | ✅ 负责 commit/push/远程同步 | ✅ 自己那轮也要推 | ❌ 不再手动操作 Git | `git log` |
| 13 | 文档维护 | 架构/ADR/协议/工程档案 | 只维护代码内 JSDoc 与报告 | — | 仓库内文档 |
| 14 | 定时巡检 | 两个定时任务（评审 / 仓库守护） | — | — | 自动化任务 |

## 三、决策权归属（避免互相等）

| 决策类型 | 谁定 | 说明 |
|---|---|---|
| 做什么、不做什么 | 王上 | 范围变更必须经王上 |
| 技术方案、架构分层 | 锻码师 | Codex 有异议提 ADR 变更申请，不擅自偏离 |
| 文件内具体实现（算法、命名细节） | Codex | 报告里说明即可，不需事先请示 |
| 任务是否通过 | 锻码师 | 依据 `ACTIVE.md` 验收清单，不依 Codex 自述 |
| 阶段推进 | 锻码师 | `STATE.json.stage` 为 Codex 禁区 |
| 上线/交付对外 | 王上 | — |

## 四、明确禁止的越界

| 越界行为 | 谁可能犯 | 为什么禁止 |
|---|---|---|
| 架构师直接写业务代码 | 锻码师 | 破坏「设计-实现-评审」三权分立，自审自过 |
| Codex 自行扩大任务范围 | Codex | 范围蔓延，契约失效 |
| Codex 改 `STATE.json` 的 `stage` 或 `review/**` | Codex | 篡改事实源与评审记录 |
| Codex 用 `@ts-ignore`/关 strict 过编译 | Codex | 掩盖缺陷 |
| 王上手动改仓库文件 | 王上 | 绕过版本控制，状态漂移 |
| 任何一方 `push --force` | 双方 | 不可逆 |

## 五、一轮完整回合的时序

```
锻码师: 写 ACTIVE.md ──► STATE=READY ──► push
                                    │
                          Codex pull / 打开仓库
                                    │
                         读 AGENTS.md → 读 STATE
                                    │
                            实现 14 个文件
                                    │
                        build 通过 → 写 REPORT
                                    │
                        STATE=SUBMITTED → push
                                    │
              锻码师定时任务(每小时) 或 会话内评审
                                    │
                   读 REPORT + git show + grep 校验
                                    │
                  写 REVIEW ──► 判定 ──► STATE 更新 ──► push
                                    │
                    ┌───────────────┴───────────────┐
              CHANGES_REQUESTED                 APPROVED
                    │                               │
        Codex 只修🔴🟠，追加报告                锻码师下发下一任务
                    │                               │
              STATE=SUBMITTED                  STATE=READY(新任务)
```

## 六、例外与升级

| 情况 | 处理 |
|---|---|
| Codex 发现契约自相矛盾 | 报告「待确认」小节，停在该处，不猜 |
| 实现必须偏离 ADR | 提 ADR 变更申请，锻码师确认后才动 |
| 评审两轮仍未通过 | 锻码师介入拆小任务，或改契约降低单轮范围 |
| 定时任务连续失败 | 锻码师排查，必要时改协议触发方式 |
