# TASK-032 实现报告 — G45 ARXML 多模块导入（用户实测失败修复）

- 反馈来源：用户导入 `CanIf.arxml`、`ZZ_调研测试_DEL.arxml` 均失败

## 病因（实测）

| 文件 | 实际 | 原失败原因 |
|---|---|---|
| `ZZ_调研测试_DEL.arxml` | 12 个模块段的工程级文件 | 导入器硬性要求「有且仅有一个模块」 |
| `CanIf.arxml` | 1 个模块段 + 合法的 `-REF` 引用 | ①CanIf 定义未加载；②文件用 `/AUTOSAR/CanIf` 简写路径，与内置 `/AUTOSAR/EcucDefs/CanIf` 精确匹配失败 |

## 交付

| 项 | 实现 |
|---|---|
| 扫描 | `scanArxmlModules()`：只解析模块头（短名/定义路径/release/UUID），忽略 `-REF` 变体 |
| 单模块导入 | 定义未加载时**按文件版本自动加载**（`ensureModuleDefinition`）；路径匹配加**短名兜底**（`/AUTOSAR/<模块>` 与 EcucDefs 路径等价） |
| 工程级导入 | 弹窗列出全部模块（勾选、默认全选）：标注「已有同模块配置 / 需自动加载 / 版本不一致将跳过」；逐模块可选 覆盖 / 新建副本 / 跳过 |
| 缺失定义 | 从内置库自动加载；库中确实没有才跳过并在结果中说明 |
| 版本不一致 | **按用户裁定直接报错并跳过该模块**（不跨版本套用） |
| 落库 | 导入后**自动并入当前工程**（setUuids + moduleShortNames + 生成/验证偏好），切换为当前配置集并校验 |
| 空壳识别 | 文件仅含模块壳（配置在外部引用）时提示「已建空配置集」，不伪装成有内容 |
