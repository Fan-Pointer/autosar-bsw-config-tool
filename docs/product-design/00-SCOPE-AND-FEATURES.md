## 1. 目标 / 角色 / 场景 / 边界

| 项 | 定稿 |
|---|---|
| 一句话目标 | 汽车电子工程师在**浏览器本地**完成 AUTOSAR BSW 模块（首期 Dem，官方 67 容器）的配置编辑、校验、标准文件（ECUC ARXML 4.4.0）与通用可编译 C 代码的产出 |
| 角色 | 单用户本地工程师（无账号、无协同） |
| **多模块澄清（用户 2026-11-06）** | **「单一配置方案」仅排除 Pre/Link/Post-build 变体，不限制 BSW 模块数量**（USER-REQUEST-20261106-MULTI-MODULE.md）：模块定义从 AUTOSAR ECUC ARXML 脚本抽取（单文件可含单/多模块），同一工作区可添加多个模块并存；通用定义驱动能力与特定模块验证范围分开声明，不因此扩成全 BSW 专用语义支持 |
| 核心场景 | S1 打开/新建配置→S2 编辑（树+表单+引用+CHOICE）→S3 校验修错→S4 导出 ARXML/JSON/CSV→S5 生成 C 代码；辅以旧数据恢复、搜索定位、批量修改、撤销重做 |
| 边界（不纳入，G28–G30） | 云端/分享/回收站/账号；DBC/LDF/CDD 解析；变体（Pre/Link/Post-build）；供应商 ABI 与 DaVinci 兼容承诺；全 BSW/RTE/OS/MCAL |
| 验收口径 | XML 语法合法 / 匹配官方 XSD（能力具备后）/ 配置语义与引用完整 / 通用可编译 C（gcc）——供应商互操作与集成**显式声明未验证** |
| 版本基线 | 发布 **CP 4.4.0**；命名空间 `http://autosar.org/schema/r4.0`（TPS_ASR_00011/00017）；CHOICE 值侧按 CP 4.4.0 `TPS_ECUC_03020`/Example 2.33；数据库 schema 版本、AUTOSAR release、定义来源 hash 三者分开表达 |

## 3. 功能优先级总表

- **P0（S1–S3 覆盖）**：数据安全、输出正确性、标准口径、测试可信 —— 不达成不进入交付阶段
- **P1（S4–S7 覆盖）**：可用性闭环、效率、交付质量
- **不纳入**：G28（G29 经用户 2026-11-06 裁定修订为 G38 参考数据导入）；**后续**：G30
